# DECISION_INDEX.md — index of LEARN comments

> Maintained by the executor (dsh / flash v4). Every `LEARN[n]` comment in the code is registered here. LEARN comments explain **why** major design choices were made — they are teaching comments for the human reading the code later.
>
> They are **separate from normal documentation**: JavaDoc, docstrings, and function descriptions describe *what* the code does and are still written as usual. LEARN comments describe *why it is done this way and what the alternatives were*.
>
> Process-level deviations (change of scope or plan) do **not** go here — they go in `DECISIONS.md`.

## When a LEARN comment is required

- Architecture and design-pattern choices (why this structure, why this pattern)
- Main algorithms chosen for a task — not trivial ones, but the main ones certainly
- Any decision where a reasonable alternative existed and was rejected

Not required: trivial glue code, obvious one-liners, standard library usage.

## Comment format

Place near the decision point in the code:

```text
// LEARN[3]: <why this approach was chosen>
// Alternatives considered: <what else was possible>
// Pros of chosen approach: ...
// Cons of chosen approach vs alternatives: ...
// See also: LEARN[1]
```

- **Length:** as long as it needs to be. Never sacrifice understanding for brevity.
- **Cross-referencing:** if an earlier LEARN comment already explains the background, reference it (`See also: LEARN[k]`) instead of writing the same explanation twice.
- **Style:** adjust the comment syntax to the language (`//`, `#`, `/* */`, docstring-adjacent block) — the `LEARN[n]` marker must stay exactly in that format so the index and search tools can find it.

## Rules

- Numbers are never reused. If the code is deleted, mark the row `removed in M<n> — reason` instead of deleting it.
- If a milestone changes code governed by an existing LEARN comment: update the comment and note the revision in this table. If the *decision itself* changed, add a new LEARN entry that references the old one.
- New LEARN comments from a milestone are listed in `STATUS.md` and committed with that milestone.
